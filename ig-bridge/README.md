# IG Bridge (MediaScanner)

Расширение Chrome для отдельного профиля «IG Bridge» на офисном ПК. Держит
WebSocket к шлюзу `ig_bridge` (`wss://ig-bridge.mediascanner.kz/ws`) и
выполняет команды сервера на чтение Instagram во вкладке instagram.com этого
профиля. Куки из браузера не уходят: сервер получает только признак входа,
`ds_user_id`, sha256 от `sessionid` и срок сессии.

Подробности: план Instagram v2, задачи 01 (протокол шлюза) и 02
(поведение расширения).

## Что внутри

| Файл | Зачем |
|---|---|
| `background.js` | соединение со шлюзом, очередь команд, алармы, состояние |
| `lib/ops.js` | белый список операций: проверка аргументов, запрос, ужимание ответа |
| `lib/tab.js` | закреплённая вкладка instagram.com, профиль-маяк |
| `lib/state.js` | настройки, бейдж, уведомления |
| `content/capture.js`, `content/relay.js` | захват `doc_id` и формы `variables` со страницы |
| `popup.*`, `options.*` | окно состояния и настройки |
| `tests/ops.test.mjs` | тесты белого списка: `node --test extension/ig-bridge/tests/ops.test.mjs` |

Чистый JS без сборщика и зависимостей.

## Установка в профиль Chrome «IG Bridge»

Всё делается в отдельном профиле Chrome под Instagram.

1. **Вход в Instagram.** Открыть instagram.com: должна быть лента, а не форма
   входа; если просит подтверждение, пройти. Лучше выделенный аккаунт под
   мониторинг, не личный. Дальше в этом профиле не выходить из аккаунта, не
   чистить куки, не включать VPN и не пользоваться профилем для своих дел.
2. **Папка профиля.** `chrome://version` → «Путь к профилю» → последняя часть
   (например, `Profile 2`). Нужна для автозапуска (п. 6).
3. **Папка расширения.** Скопировать `extension/ig-bridge` в
   `C:\IG-Bridge\extension` (стабильный путь вне репозитория: если папка
   переедет, Chrome потеряет распакованное расширение). Если стоит
   `ig-ws-spike` от проверки 06.10, удалить его.
4. **Загрузка.** `chrome://extensions` → «Режим разработчика» → «Загрузить
   распакованное расширение» → `C:\IG-Bridge\extension`. Закрепить иконку
   (пазл → булавка).
5. **Настройки расширения:** адрес шлюза по умолчанию, токен (значение
   `IG_EXTENSION_TOKENS` с сервера), метка `office-pc-1`, ник аккаунта.
   «Сохранить» → «Проверить» → «Instagram отвечает, сессия живая».
6. **Автозапуск.** Chrome → Настройки → Система → «Продолжать работу фоновых
   сервисов после закрытия Google Chrome»: вкл. Ярлык в автозагрузке Windows
   (`Win+R` → `shell:startup`):
   `"C:\Program Files\Google\Chrome\Application\chrome.exe" --profile-directory="Profile 2"`
   (папку из п. 2). Ярлык можно создать PowerShell:

   ```powershell
   $s = (New-Object -ComObject WScript.Shell).CreateShortcut("$env:APPDATA\Microsoft\Windows\Start Menu\Programs\Startup\IG Bridge.lnk")
   $s.TargetPath = "C:\Program Files\Google\Chrome\Application\chrome.exe"
   $s.Arguments = '--profile-directory="Profile 2"'
   $s.Save()
   ```
7. **Сон Windows** отключить:
   `powercfg /change standby-timeout-ac 0` и `powercfg /change hibernate-timeout-ac 0`.
8. **Обновление расширения:** заменить файлы в `C:\IG-Bridge\extension` →
   `chrome://extensions` → «Обновить».
9. **Резерв (позже):** второй профиль Chrome со вторым аккаунтом и тем же
   расширением (метка `office-pc-1b`) станет на сервере второй сессией и
   удвоит бесплатную ёмкость.

Если Chrome при старте предупреждает о расширениях в режиме разработчика,
закрыть предупреждение: на работу не влияет.

## Бейдж на иконке

| Бейдж | Что значит | Что делать |
|---|---|---|
| пусто | работает | ничего |
| `SET` | не настроено | открыть настройки, вписать токен |
| `IN` | вышли из Instagram | войти в Instagram в этом профиле |
| `!` | Instagram просит проверку | открыть instagram.com, пройти проверку |
| `EXP` | сессия не работает | выйти и войти в Instagram заново |
| `OFF` | выключено на сервере | ничего, решение сервера |
| `ERR` | нет связи с сервером | проверить интернет; расширение переподключится само |
| `KEY` | неверный токен | исправить токен в настройках |

## Ограничения, зашитые в расширение

- Только операции `topsearch`, `profile_posts`, `comments`, `media_info`,
  `tag_recent`, `top_serp`, `verify`; остальное `not_allowed`.
- `doc_id` для ленты профиля берётся только со страницы, не от сервера.
- Между командами не меньше 5 с, не больше 200 команд в час.
- В консоль не пишутся значения кук, токены страницы и токен шлюза.
